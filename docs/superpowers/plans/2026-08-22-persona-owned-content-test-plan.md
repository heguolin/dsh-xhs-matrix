# 人设拥有内容资产 v4 测试计划

## 目标

验证知识库、爆款、人工权重和写作安全规则确实由人设拥有；迁移不丢数据；两阶段创作只展示最终审校稿；UI 在 Harness 窄宽环境可用。

## 必测数据场景

1. 两个账号绑定同一人设，知识库与爆款数量、内容 id、权重完全一致。
2. 一个账号换绑到另一人设，旧内容仍属于原人设，来源账号快照保持不变。
3. 删除账号后，人设资产和 MetricSnapshot 保留；账号会话、草稿和采集配置删除。
4. v3 内容对应账号缺失或无人设时，完整记录进入 pending；归属后 id、正文、时间和权重不变。
5. 手动爆款不可通过请求覆盖默认状态与权重；保存后为 accepted+5。
6. 自动爆款默认 pending+1；人工修改 weight 不改变 score。
7. 参考素材命中违禁词只显示警告；最终生成稿命中时消息和草稿均不落库。
8. 相同 requestId 完成后重试不调用模型；进行中重复返回 409；失败后允许原 requestId 重试。

## 浏览器验收脚本

1. 打开矩阵面板，创建账号“验收账号”，绑定既有人设；无需刷新即在侧栏出现并自动选中。
2. 进入知识库，确认顶部显示资产人设和“由 N 个账号使用”；切换人设后列表同步变化。
3. 导入一篇笔记，选择目标人设和来源账号；把权重从 1 调到 5，切换到同人设另一个账号后仍显示 5。
4. 进入爆款池，手动新增标题与正文；保存后立即显示“已采纳”和权重 5。
5. 把一条采集内容权重调为 4，确认机器评分不变化。
6. 进入人设配置，自定义写作风格；填写结尾钩子约束和两个案例；添加违禁词并保存。
7. 进入创作台发送请求；观察规划、起草、去 AI 味、检查四阶段；最终稿逐步出现，原始初稿不出现在消息流。
8. 流式过程中保持底部应持续跟随；向上滚动后暂停并出现“回到最新”；点击后恢复。
9. 使用会触发违禁词的测试输出，确认质量面板标出词与位置，并禁用保存草稿。
10. 缩窄 Harness 中央面板，确认人设表单降为单栏，中文内容不逐字竖排。

## 质量评估判定

`pnpm eval:quality` 的每个样例必须同时满足：

- `requiredFacts` 全部仍在最终稿中；
- `forbiddenFacts` 全部不在最终稿中；
- 人设违禁词命中数为 0；
- 输出不包含提示词、系统消息、分析标签或“作为 AI”自述；
- 结尾符合人设钩子约束且没有强制点赞关注。

任一失败都使命令退出非零，并输出可定位的样例 id。

## 交付证据

最终报告必须包含：

- `pnpm test`、`pnpm typecheck`、`pnpm build` 的命令与退出码；
- `pnpm eval:quality` 结果或明确的未运行原因；
- 浏览器验收 10 项结果；
- v3 备份文件名和迁移后版本；
- `scripts/install.sh` 开工与收尾的相同 diff 摘要；
- 最终 `git status --short`，区分用户既有变化与本次实现变化。
