# 小红书矩阵：人设资产化架构设计

日期：2026-08-22  
状态：已与用户逐段确认（领域模型、混合式界面、生成质检、流式协议、异常与测试）

## 1. 背景与目标

当前系统把已发布知识库、笔记权重和爆款池绑定到账号。这个模型会让使用同一人设的多个账号重复维护内容，也会让账号换绑人设时产生错误继承。新的核心语义是：

- **人设是可复用内容资产的所有者**。
- **账号是发布、采集和会话的运营载体**。
- 多个账号绑定同一人设时，共享知识库、知识库权重、爆款池、爆款权重、写作规则、结尾互动钩子和违禁词。
- 账号删除或换绑人设，不自动删除或搬迁历史人设资产。

本次同时解决以下现有问题：

- 用户可手动向指定人设新增爆款笔记。
- 爆款池每条内容新增可编辑的 `0–5` 权重。
- 当前被误称为“钩子”的标签改为可自定义“写作风格”。
- 钩子专指结尾互动引导，支持自由约束文本与多条最佳案例。
- 生成内容执行人设级违禁词检查和二次“去 AI 味”审校。
- 创作台提供可审计的创作说明、阶段状态和最终内容流式输出。
- 创作台默认滚动到消息底部，并尊重用户主动向上查看历史的操作。
- 新增账号后立即出现在侧栏并被选中，不再依赖刷新页面。

本次不改变人工发布原则：生成结果只进入会话或草稿，不自动发布到小红书。

## 2. 采用的架构方案

采用“直接人设归属”方案：`PublishedNote` 与 `ViralItem` 以 `personaId` 为唯一内容归属，同时保留可选来源账号字段用于追踪。没有采用双归属字段作为业务主键，也不引入内容关联表。

原因：

- 与“人设是内容资产、账号是渠道”的业务语义一致。
- JSON 存储下查询和迁移路径直接，避免 `accountId` 与 `personaId` 长期漂移。
- 足以支持多账号共享、账号换绑、来源追踪和历史指标，无需引入多对多关系的额外复杂度。

## 3. v4 领域模型

存储格式由 v3 升级到 v4。

### 3.1 人设资产

#### `PublishedNote`

```ts
interface PublishedNote {
  id: string
  personaId: string
  sourceAccountId?: string
  sourceAccountName?: string
  title: string
  copy: string
  topic?: string
  contentType?: string
  sourceUrl?: string
  publishedAt: string
  source: DataSource
  weight: NoteWeight // 0 | 1 | 2 | 3 | 4 | 5
  createdAt: string
  updatedAt: string
}
```

`personaId` 是唯一归属；来源账号只用于追踪和指标采集。账号被删除后，`sourceAccountName` 快照仍可用于展示来源。

#### `ViralItem`

```ts
interface ViralItem {
  id: string
  personaId: string
  sourceAccountId?: string
  sourceAccountName?: string
  title: string
  body: string
  sourceUrl?: string
  source: 'apify' | 'manual' | 'import'
  status: 'pending' | 'accepted' | 'ignored'
  weight: NoteWeight
  score: number
  reasons: string[]
  publishedAt?: string
  collectedAt: string
  batchId?: string
}
```

默认值：

- 用户手动新增：`status = accepted`、`weight = 5`。
- 自动采集：`status = pending`、`weight = 1`。

`score` 是采集和相关性排序的机器评分；`weight` 是用户对参考价值的明确判断。两者不得互相覆盖。

#### `ViralBatch`

批次以 `personaId` 分组，保留可选 `sourceAccountId`。账号换绑人设后，旧批次仍属于采集当时的人设。

### 3.2 人设规则

`Persona` 新增或调整以下字段：

```ts
interface Persona {
  // 既有字段省略
  writingStyles?: string[]
  endingHookConstraints?: string
  endingHookExamples?: string[]
  forbiddenWords?: string[]
}
```

- `writingStyles` 支持任意新增、编辑、删除。界面可以给推荐标签，但不能限制为固定选项。
- `endingHookConstraints` 是自由文本，例如“结尾自然邀请读者一起学习，不要命令式关注”。
- `endingHookExamples` 是可增删的最佳案例列表，例如“可以一起来学习学习”。案例仅作为风格参考，不要求逐字复制。
- `forbiddenWords` 是当前人设的唯一违禁词来源；不建立全局违禁词库。

现有 `toneTags` 继续表示口癖或语气标签，不与写作风格或结尾钩子混用。

### 3.3 账号运营数据

以下实体继续以账号为业务归属：

- `Account` 及其连接、采集配置和采集状态。
- `MetricSnapshot`：继续保存 `accountId + noteId`，并增加 `accountNameSnapshot`。同一人设笔记可拥有不同来源账号的指标历史；账号删除后名称快照仍可解释历史数据。
- `Draft`：生命周期属于账号，并增加 `personaIdSnapshot` 记录生成时的人设。
- `StudioMessage`：属于账号，并增加 `personaIdSnapshot`；创作台只读取当前账号和当前人设快照同时匹配的消息，避免账号换绑后混入旧人设会话。

指标调度器按 `PublishedNote.sourceAccountId` 查找需要采集的笔记，而不是按账号当前绑定的人设反查。这样账号换绑后，旧笔记仍保留在原人设，且其历史指标不会被错误改归属。

### 3.4 待归属数据

v4 增加独立 `pendingOwnership` 集合。迁移时无法解析人设的知识库或爆款条目进入该集合，不进入正常人设资产查询。

每条待归属记录保存：

- 原始内容类型和完整载荷。
- 原 `accountId` 与可获得的账号名称。
- 无法归属原因。
- 迁移时间。

用户选择目标人设后，服务将记录原子地移入对应正式集合。原始内容 ID 保持不变，已有指标仍可通过 `noteId` 关联。

## 4. 领域不变量与生命周期

1. 正常知识库和爆款条目必须引用存在的人设。
2. 内容权重必须是 `0–5` 整数。
3. 同一人设的所有账号读取同一份知识库、爆款与权重。
4. 账号换绑人设只影响后续导入、采集和生成；历史资产留在原人设。
5. 内容转移只能通过显式的单篇或批量“转移到其他人设”操作完成。
6. 删除账号时保留人设资产和只读历史指标；删除账号自己的连接、采集配置、会话和草稿。删除后不得再向该账号 ID 追加新指标。
7. 删除人设前若仍有内容资产或绑定账号，必须阻止删除并提示先转移或处理，避免制造新的悬空数据。
8. 手动爆款直接视为用户确认过的高价值参考，因此默认已采纳且权重为 5。
9. 自动采集内容必须先审核，未采纳内容不得进入创作上下文。
10. 创作参考按人工权重优先；机器 `score` 只用于候选排序。

## 5. 存储迁移

### 5.1 v3 → v4

首次迁移步骤：

1. 读取并完整校验 v3 文件。
2. 在同目录创建带时间戳的 v3 备份文件。
3. 为每条旧 `PublishedNote` 和 `ViralItem` 查找原账号。
4. 若账号存在且有有效 `personaId`，写入该人设，并保存来源账号 ID 与名称快照。
5. 若账号不存在、未绑定人设或人设引用失效，写入 `pendingOwnership`。
6. 旧 `ViralItem` 增加 `weight = 1`；已有审核状态保持不变。
7. 旧 `hookStyles` 迁移为 `writingStyles`；旧 `endingStyle` 迁移为 `endingHookConstraints`。
8. `Draft` 和 `StudioMessage` 尽可能按账号当时的人设补充 `personaIdSnapshot`；无法确认时保留记录但标记为历史未归属，不注入当前创作上下文。
9. 原子写入 v4 文件，完成后再切换内存状态。

多个账号指向同一人设时，迁移后的内容自然合并到同一人设查询结果中；内容 ID 不重写，权重不合并或平均。

迁移失败时继续使用原 v3 文件，不能留下部分 v4 状态。备份不得覆盖已有备份。

## 6. 服务边界

### 6.1 `PersonaAssetService`

负责知识库、爆款池、权重、批次、显式转移和待归属处理。所有公开方法以 `personaId` 为主键，并集中执行人设存在性与内容归属校验。

### 6.2 `CollectionService`

采集仍由账号发起：读取账号采集配置和当前人设，调用 provider，使用该人设规则与高权重知识库排序，然后把批次和候选写入人设资产。它不拥有内容删除或转移逻辑。

### 6.3 `ContentQualityService`

负责：

- 构造自然化审校请求。
- 对最终输出执行确定性的逐词扫描。
- 返回命中词、位置和检查时间。
- 判定内容是否允许保存草稿。

参考素材中的违禁词只产生警告；待发布内容命中违禁词时禁止保存。

### 6.4 `StudioService`

负责账号会话、当前人设解析、上下文选择、模型调用、结构化流式事件和草稿保存。它通过上述服务读取资产和执行质检，不直接维护人设资产集合。

## 7. API 与工具契约

### 7.1 新契约

- 知识库列表、导入、调权和转移使用 `personaId`。
- 爆款列表、审核、调权、批次删除、手动新增和转移使用 `personaId`。
- 手动新增爆款至少需要标题和正文；来源链接、发布时间可选。
- 采集请求仍使用 `accountId`，服务端解析采集当时的人设。
- 待归属数据提供列表与显式归属接口。

### 7.2 兼容期

现有按 `accountId` 查询知识库或爆款的路由和工具保留一个版本兼容期，内部解析为账号当前人设，并在响应中标明解析后的 `personaId`。同时传入 `accountId` 和 `personaId` 且二者不一致时返回 `409`，不得静默选择其中之一。

`xhs_today` 继续以账号为入口，但上下文改为该账号当前人设的共享资产。`xhs_notes` 和 `xhs_virals` 增加直接按人设查询能力，并保留账号兼容参数。

## 8. 混合式界面

保留当前账号侧栏和账号工作区。知识库与爆款池改为“人设资产视图”：

- 顶部提供人设选择器，默认选择当前账号绑定的人设。
- 切换账号时，两个资产页默认跟随到新账号的人设；用户也可在页面内临时切换其他人设。
- 显示“该人设由 N 个账号使用”。
- 知识库导入目标是当前选中人设，可选来源账号。
- 爆款池增加“手动新增”，保存后立即以已采纳、权重 5 展示。
- 两类内容均提供 `0–5` 权重、来源账号、违禁词警告和显式转移操作。
- 只有存在遗留记录时才显示“待归属”入口。

人设配置页：

- 将截图所示的“反常识、痛点切入、真实对比、教程结构、经验清单、互动提问”等区域改名为“写作风格”。
- 风格标签允许自由输入、编辑和删除；预设只作为建议。
- 单独提供“结尾互动钩子约束”和可增删的“最佳案例”。
- 违禁词以标签或分行输入方式编辑，保存到当前人设。

创作台侧栏分别展示写作风格、结尾钩子规则和参考数量，不再把写作风格标成钩子。

## 9. 账号新增与创作台滚动

### 9.1 新增账号即时同步

`AccountsDialog` 创建成功后返回完整账号或新 ID，并 `await` 父级刷新。父级完成列表更新后立即选中新账号。弹窗内部列表与父级侧栏不能依赖两份互不通知的本地状态。

失败时保留表单内容并显示错误；不得显示成功提示后让侧栏保持旧数据。

### 9.2 默认滚动到底部

创作台增加底部锚点和自动跟随状态：

- 首次进入、账号或人设会话切换、历史加载完成时滚到底部。
- 新消息和最终稿流式增量到达时，如果用户仍在底部附近则持续跟随。
- 用户主动向上滚动超过阈值后暂停自动跟随，并显示“回到最新”操作。
- 用户点击“回到最新”或重新接近底部后恢复跟随。

## 10. 生成与质量管线

创作采用两阶段模型调用。

### 10.1 第一阶段：计划与初稿

上下文按账号找到当前人设，并加载：

- 人设定位、受众、专业领域和内容方向。
- 自定义写作风格。
- 结尾钩子约束和最佳案例。
- 人设违禁词。
- 高权重已发布知识库。
- 已采纳且按人工权重优先的爆款参考。

提示词禁止空泛总结、僵硬模板、机械排比、过度感叹、虚假亲身经历和无事实依据的断言。第一阶段流式产生可展示的创作计划，同时在服务端缓冲原始初稿；原始初稿不写入会话。

### 10.2 第二阶段：去 AI 味审校

第二次模型调用接收原始初稿和人设规则，负责自然化改写。它可以调整句式、节奏、结构和结尾互动，但不得新增事实或伪造经历。

审校后的最终稿再由程序扫描当前人设违禁词：

- 无命中：允许写入助手消息和保存草稿。
- 有命中：展示命中词与位置，标记未通过并禁止保存。
- 审校调用失败：保留服务端初稿用于本次重试，界面标记“未完成质检”，禁止保存。

手动或导入的知识库、爆款只显示违禁词警告，不阻止入库；生成模型不得复用参考素材中的命中表达。

草稿保存轻量 `qualityReport`：审校状态、违禁词命中、检查时间和使用的人设快照。

## 11. 结构化流式协议

SSE 使用有类型的事件：

- `evidence`：人设、知识库和爆款引用及选择理由。
- `plan_delta`：受众、选题角度、正文结构和结尾钩子策略的可审计创作说明。
- `phase`：`planning`、`drafting`、`polishing`、`checking` 等阶段进度。
- `content_delta`：只包含审校后的最终文案增量。
- `quality`：审校状态、违禁词命中和保存许可。
- `done`：最终消息 ID、封面提示词、依据和质量摘要。
- `error`：可恢复错误、所在阶段和是否允许重试。

界面展示的是结构化创作说明和可验证依据，不展示冗长、不可验证的模型内部推理原文。

连接中断时不保存半截助手消息。客户端可重试当前请求；服务端通过请求 ID 防止重复落库。只有收到 `done` 且质量通过的最终内容才能保存为草稿。

## 12. 错误处理

- 账号未绑定人设：阻止采集和创作，提示先绑定。
- 人设不存在或归属不匹配：返回明确的 `404` 或 `409`，不得自动改归属。
- 人设仍有绑定账号或内容时删除：返回 `409` 并给出待处理数量。
- 迁移无法确定归属：进入 `pendingOwnership`，不丢弃。
- 模型第一阶段失败：结束本次请求，不写消息。
- 模型审校失败：显示可重试状态，不允许保存未审校内容。
- 违禁词未通过：返回精确命中项和位置，不自动吞掉内容或伪装通过。
- SSE 中断：不保存不完整助手消息；历史中只出现完整结果。

## 13. 测试与验收

### 13.1 迁移和存储测试

- 多个账号绑定同一人设时，v3 内容合并到同一人设查询结果，ID 和既有权重保持不变。
- 未分配人设、账号缺失和人设引用失效的数据进入待归属集合。
- v3 备份先于 v4 原子写入产生；失败后原文件可继续加载。
- 手动爆款默认 `accepted + weight 5`；采集爆款默认 `pending + weight 1`。
- 账号换绑和删除不移动或删除人设资产。
- 人设有依赖时删除被阻止。
- 显式单篇和批量转移保持内容 ID、来源和指标关联。

### 13.2 服务和路由测试

- 人设主键查询、调权、审核、导入、手动新增、批次删除和转移。
- 账号兼容参数正确解析当前人设；冲突参数返回 `409`。
- 采集结果写入采集当时的人设，并保留来源账号。
- 指标调度按 `sourceAccountId` 工作，不受账号换绑影响。
- 创作上下文只包含当前账号当前人设的会话，以及该人设共享资产。
- 参考排序优先使用人工权重，机器分数不覆盖人工权重。

### 13.3 质量与流式测试

- 两阶段调用顺序、SSE 事件顺序和最终 `done` 负载正确。
- 第一阶段原始初稿不会作为 `content_delta` 泄漏或写入历史。
- 人设违禁词命中和位置准确；未通过时不能保存草稿。
- 审校失败、SSE 中断和重试不会产生半截或重复消息。
- 固定内容样例验证自然化规则：减少模板套话、空泛总结、机械排比和虚假经历，同时不改变事实。

“去 AI 味”是模型审校与可读规则共同形成的质量约束，不宣称存在百分之百准确的单一算法判定。

### 13.4 前端测试

- 新建账号后弹窗和侧栏立即同步并选中新账号。
- 知识库、爆款池默认跟随当前账号人设，也可独立切换人设。
- 同人设多个账号看到相同内容与权重。
- 写作风格支持任意标签；结尾钩子约束和案例独立编辑。
- 手动新增爆款的默认状态和权重正确显示。
- 创作台初始、历史加载和正常流式输出自动位于底部。
- 用户上滚后暂停跟随，“回到最新”恢复跟随。
- 结构化创作说明、阶段进度、最终稿和质量报告按顺序显示。

## 14. 完成标准

满足以下条件才视为改造完成：

1. 存储和所有主要查询不再以账号作为知识库或爆款池的内容归属。
2. 同人设多账号真实共享内容和人工权重。
