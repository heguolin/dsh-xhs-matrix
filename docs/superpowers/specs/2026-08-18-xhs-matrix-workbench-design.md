# 小红书矩阵工作台扩展设计

## 1. 目标

将小红书矩阵从账号档案与草稿管理扩展为按真实账号隔离的内容运营工作台：账号绑定、已发布内容知识库、指标采集、人设配置、外部趋势选题、百万上下文创作台和人工可编辑草稿形成闭环。

矩阵创作台复用 DeepSeek Harness 当前配置的模型、模型提供商、Base URL、凭据和推理参数，但只处理矩阵创作内容，不复用 Harness 主工作区的对话记录、工作区路径、文件上下文或非矩阵工具。

## 2. 已确认的边界

- 每个矩阵账号独立管理真实小红书账号连接、人设、知识库、权重、趋势结果、草稿和创作会话。
- 读取小红书后台真实数据需要账号授权；在没有明确合规授权 API 前，后台数据使用 CSV/JSON 手动导入兜底。
- Apify 作为首个外部数据适配器，负责公开内容、外部趋势和爆款选题发现；Apify 不被视为小红书官方后台授权接口。
- 定时任务只更新已发布笔记的指标和采集状态，不定时生成内容、不自动发布。
- 已发布笔记知识库只保存用户自己已经发布的内容；Apify 外部样本单独保存，不自动进入本地知识库。
- 黑名单独立模块删除。避免规则属于账号人设和选题标准，低权重或零权重历史笔记作为负向经验。
- 所有自动生成结果先进入可编辑草稿流程，由人工审核和发布。
- 创作台支持百万级上下文设计，但实际可用上限以当前配置模型能力为准；不得静默截断或虚假显示百万上下文。

## 3. 用户流程

```text
添加矩阵账号
  ↓
绑定真实小红书主页或账号标识
  ↓
配置人设、文案风格、钩子风格和选题标准
  ↓
授权数据源或导入后台数据
  ↓
建立该账号的已发布笔记知识库
  ↓
设置每篇笔记人工权重 0-5
  ↓
Apify 获取外部趋势和候选选题
  ↓
按当前账号人设、历史权重和外部信号分析
  ↓
在矩阵创作台主动发起生成
  ↓
LLM 生成原创内容
  ↓
人工编辑并保存草稿
  ↓
人工发布
  ↓
定期更新已发布笔记指标
```

## 4. 领域模型

### 4.1 矩阵账号

矩阵账号是内容生产和数据隔离的根节点，至少包含：名称、真实账号主页链接或标识、绑定人设、连接状态、数据源配置、采集配置和启用状态。

账号连接状态至少区分：未绑定、已绑定未授权、已授权、待导入后台数据、采集失败和已失效。公开采集、后台导入和未来授权 API 的数据来源必须在记录中明确标记。

### 4.2 人设配置

人设使用结构化字段与系统提示词并存：账号定位、目标受众、擅长领域、内容方向、文案风格、语气与用词习惯、钩子风格、正文结构、结尾互动方式、禁用内容或表达、默认话题标签和选题筛选标准。

人设编辑必须支持自定义文本，钩子风格支持多选和自定义。生成请求时由 Host 组装为当前账号专属系统提示，不把其他账号的人设带入请求。

### 4.3 已发布笔记知识库

知识库只保存当前账号已经发布的笔记：标题、完整文案、选题、内容类型、发布链接、发布时间、来源、指标快照和人工权重。

权重为账号级人工字段，取值 0-5：5 分优先参考成功规律，3-4 分正常参考，1-2 分弱参考，0 分作为负向经验并尽量避开同类方向。权重不会被系统根据流量自动覆盖，也不跨账号共享。

指标采用追加快照，不覆盖历史记录。快照至少包括阅读、点赞、收藏、评论、分享（数据源支持时）、采集时间、来源和采集状态。

### 4.4 外部趋势样本

外部样本包含来源、Actor、来源链接、标题、内容摘要、发布时间、公开互动指标、关键词、内容类型、采集时间和原始状态。只保存生成分析所需的核心字段，避免保存评论者等非必要个人信息。

外部样本与本地知识库分离。人工可以收藏外部样本作为参考，但仍保留外部来源标记。

### 4.5 草稿

草稿属于单个矩阵账号，包含标题、正文、话题标签、封面提示词、生成依据、编辑版本、状态和创建/更新时间。草稿状态不代表已发布；只有人工发布后才回填发布链接和指标。

## 5. 数据源与采集

### 5.1 Apify 适配器

核心矩阵逻辑不直接依赖某个 Actor 的返回格式。数据源接口负责提交任务、读取结果、标准化字段、返回采集状态和记录来源。Apify 为首个实现，Actor ID、API Token、采集频率、单次最大数量、并发和预算为 Host 配置。

Apify 用于搜索公开笔记、获取公开账号笔记列表、读取公开互动指标和发现外部趋势。它不能被宣称为后台真实数据授权来源。

### 5.2 后台数据导入

在没有可靠授权 API 时，支持按账号导入 CSV/JSON。导入数据必须经过字段校验、账号归属确认、笔记去重和来源标记；导入失败不能部分覆盖已有历史数据。

未来接入商业或官方授权 API 时，新增适配器而不改变知识库、指标快照、权重和生成流程。

### 5.3 定时任务

定时任务按账号独立配置周期和最大采集量。任务只负责：检查数据源、提交采集、读取 Dataset、标准化结果、匹配已发布笔记、追加指标快照和更新采集状态。

失败时保留历史数据和人工权重，显示最近成功时间与失败原因，下次继续尝试；不因一次失败自动切换供应商，不触发生成或发布。

API Token 只保存在 Host 端，不发送到 Client，不写入会话记录或知识库。

## 6. 选题与生成

主动触发“找选题”或“创作”时，系统读取当前账号的人设、选题标准、历史权重和最新外部趋势，生成搜索关键词和筛选条件，并对候选给出可解释推荐分。

推荐依据至少包括：人设相关性、选题相关性、外部互动表现、内容时效性、历史高权重内容相似度和账号重复度。每条候选都展示推荐理由，允许人工编辑选题后再生成。

LLM 接收的参考材料包括当前账号人设、相关已发布笔记、人工权重、指标趋势和外部趋势摘要。权重高的笔记用于学习成功规律，权重为 0 的笔记用于识别应避免方向。外部内容只能用于参考选题、结构、用户需求和趋势，不得复制原文、图片、独特经历或仅替换词语改写。

生成结果必须是原创草稿，并显示使用的人设规则、本地笔记和外部趋势来源。

## 7. 矩阵创作台

### 7.1 隔离原则

创作台是矩阵面板内的独立 Tab。它按账号持久保存独立会话，复用 Harness 模型配置但不复用主工作区的聊天记录、文件上下文、路径、系统提示词或 Shell、SSH 等工具。

创作台系统提示明确限定为账号人设、已发布内容、外部趋势、选题分析、文案创作和草稿编辑。账号 A 的会话、知识库和人设不得进入账号 B。

### 7.2 上下文

创作台支持完整知识库模式和创作模式。完整知识库模式用于深度复盘；创作模式用于按当前选题选择相关内容、高权重样本和外部趋势。百万级上下文模型可加载大规模账号内容，但发送前必须读取模型实际上下文上限，超过上限时明确提示并采用可见的摘要或分批方式，不得静默截断。

上下文包括：当前账号资料、人设规则、已发布笔记、指标历史、人工权重、外部趋势样本、当前会话和当前草稿。只注入矩阵相关内容。

### 7.3 操作权限

创作台只开放查询当前账号、查询当前账号知识库和指标、获取外部趋势、生成内容、保存或更新草稿等矩阵操作。不开放文件系统、Shell、SSH 或主工作区工具。生成不会自动保存，只有明确点击保存草稿后才落库。

## 8. 前端视觉与交互

### 8.1 视觉方向

采用“小红书品牌工作台”方向：暖白和浅粉背景、品牌红作为主要行动色、白色内容卡片、柔和边框和胶囊标签。信息密度适中，强调内容运营的亲切感和可读性。

### 8.2 混合布局

使用“运营总览 + 专属创作台”的混合布局。左侧保留账号切换和模块导航；总览显示多账号状态、指标、知识库表现、趋势选题和草稿摘要；点击创作台后进入沉浸式对话布局，但保留账号边界和矩阵导航。

模块包括：账号总览、真实账号连接、已发布知识库、趋势选题、专属创作台、草稿箱和人设配置。黑名单 Tab 和相关入口不保留。

### 8.3 人设页面

人设页面采用左右结构：左侧编辑定位、系统提示词和目标受众；右侧编辑文案风格、钩子风格、正文结构、选题标准、禁用表达和默认话题。字段可独立保存，并提供保存状态反馈。

### 8.4 知识库页面

知识库页面展示笔记标题、缩略信息、发布时间、指标摘要、最近采集状态和权重。支持按全部、权重高、待补指标和最近发布筛选。权重 0-5 可直接点击调整，修改后明确提示其将影响下一次推荐。

### 8.5 选题页面

选题页面展示 Apify 候选、推荐分、来源、匹配人设、匹配历史样本和推荐理由。支持刷新采集、编辑候选、收藏外部参考和主动进入创作台。采集失败保留上一次结果并提供重试。

### 8.6 创作台页面

创作台采用三栏布局：左侧账号与模块导航，中间最大化对话区，右侧展示当前人设、知识库、权重规则、外部趋势、引用来源和生成结果。顶部持续显示当前账号和“仅矩阵内容”隔离提示。

对话区支持选题分析、文案生成、局部修改、草稿生成和继续追问。右侧引用卡片显示使用的本地笔记、人工权重和外部趋势来源。结果通过“打开草稿编辑”或“保存为草稿”进入下一步。

### 8.7 草稿页面

草稿编辑页面正文优先，标题、正文、话题标签和封面提示词可直接修改。提供重写标题、优化开头、调整语气和补充标签等局部操作。右侧展示生成依据和编辑提醒。保存后保持草稿状态，不自动发布。

### 8.8 状态反馈

账号连接状态区分已连接、待导入后台数据和采集失败；数据来源区分公开采集、后台导入和未来授权。采集任务显示进行中、完成、失败和重试。草稿保存成功、失败和未保存编辑内容必须有明确反馈。

## 9. 错误处理与安全

- 第三方采集失败不删除历史指标，不修改权重，不触发生成。
- LLM 失败保留候选选题和编辑器内容，允许重试或手动编辑。
- 没有合适选题时说明是相关性不足、重复度过高还是数据不足。
- 不把账号密码、Cookie、API Token 写入 Client、会话记录、草稿或知识库。
- 不保存不必要的评论者个人资料。
- 所有采集数量、并发、频率和预算均可配置，并在界面显示任务状态。
- 对外部内容只做原创创作参考，不复制原文或受保护素材。

## 10. 测试范围

需要覆盖多账号隔离、人设编辑、真实账号连接状态、CSV/JSON 导入、公开数据与后台数据来源标记、指标快照追加、Apify 标准化与失败重试、权重 0-5 校验和排序、外部样本与本地知识库隔离、百万上下文上限提示、创作台会话隔离、矩阵工具权限、草稿编辑和保存、发布状态回填，以及删除黑名单模块后的数据迁移与 UI 不回归。
